# Work History Changes

This document describes changes made to the work history functionality to address issues with duplicate schedules and to add support for temporary station assignments.

## Problem Description

There were two main issues that needed to be addressed:

1. **Duplicate Schedules**: Multiple schedules were being generated for the same team on the same date, resulting in duplicate entries in the employee_work_history table.

2. **Temporary Station Assignments**: There was no way to record when an employee temporarily takes over a station from another employee (e.g., when someone goes to the bathroom or needs to address some other issue offline).

## Changes Made

### 1. Preventing Duplicate Schedules

The `SqlAlchemyAssignmentRepository` has been modified to check for existing entries before saving new assignments. When a new schedule is generated, any existing entries for the same date are deleted first. This ensures that there is only one schedule per date.

Specifically, the following changes were made:

- Added a new method `delete_existing_entries_for_date` that deletes all existing work history entries for a specific date that were generated by the scheduler and are not temporary.
- Modified the `save_all` method to call `delete_existing_entries_for_date` for each date in the assignments before saving the new assignments.

### 2. Supporting Temporary Station Assignments

A new feature has been added to support temporary station assignments. This allows recording when an employee temporarily takes over a station from another employee.

The following changes were made:

- Added a new field `is_temporary` to the `EmployeeWorkHistoryModel` to indicate if an assignment is temporary.
- Updated the `delete_existing_entries_for_date` method to only delete non-temporary assignments, preserving temporary assignments when generating a new schedule.
- Added a new method `create_temporary_assignment` to the `SqlAlchemyAssignmentRepository` to create temporary assignments.

## Database Migration

A new database migration has been created to add the `is_temporary` field to the `employee_work_history` table. To apply this migration, run:

```bash
alembic upgrade head
```

## Usage

### Generating Schedules

Generating schedules works the same as before, but now it will automatically delete any existing non-temporary assignments for the same date before saving the new assignments.

```python
from domain.models.db import Session
from domain.repositories.implementations.sqlalchemy_assignment_repository import SqlAlchemyAssignmentRepository
from domain.services.schedule_service import ScheduleService

# Create a session
session = Session()

# Create repositories
assignment_repository = SqlAlchemyAssignmentRepository(session)

# Generate schedule
schedule_service = ScheduleService()
assignments = schedule_service.generate_schedule(...)

# Save assignments (this will delete existing non-temporary assignments)
assignment_repository.save_all(assignments)
```

### Creating Temporary Assignments

To create a temporary assignment (e.g., when an employee temporarily takes over a station):

```python
from domain.models.db import Session
from domain.repositories.implementations.sqlalchemy_assignment_repository import SqlAlchemyAssignmentRepository
from datetime import date

# Create a session
session = Session()

# Create repository
assignment_repository = SqlAlchemyAssignmentRepository(session)

# Create a temporary assignment
employee_id = 123  # ID of the employee taking over
workstation_id = 456  # ID of the workstation being taken over
assignment_date = date(2025, 5, 20)
period = 2  # Period of the day

assignment_repository.create_temporary_assignment(
    employee_id=employee_id,
    workstation_id=workstation_id,
    date=assignment_date,
    period=period
)
```
